# CI: правила полного прогона

- По умолчанию CI всегда affected — по диффу от доказанной базы.
- Полный прогон выполняется в конце спринта и выбирается ТОЛЬКО:
  - (а) точным standalone footer `CI-Full: sprint-end` отдельной строкой в сообщении реального коммита диапазона (push/PR, коммит может быть не последним в диапазоне);
  - (б) ручным Actions → CI → Run workflow с mode=sprint-full. Ручной affected footer игнорирует.
- Точный формат строки: `^CI-Full: sprint-end\r?$` — допустим только завершающий `\r` (CRLF), без начальных/конечных пробелов, ровно один пробел после двоеточия, регистр точный.
- НЕ триггер: prose в сообщении, текст в коде или diff, содержимое файлов, README, название ветки, PR description, synthetic PR merge message.
- План считается по фактическому checkout-дереву (для PR — synthetic merge); footer ищется только в сообщениях исходных коммитов.
- Squash/merge на main: footer должен быть в итоговом сообщении squash-коммита; footer исходных PR-коммитов при squash теряется.
- Полный прогон на каждую обычную фичу запрещён: обычные изменения едут по диффу.
- Недоказанная база или история (не предок, force-push, неизвестный ref, расхождение checkout/head вне PR-семантики) = ошибка плана, а не FULL и не пустой зелёный план.
- Подробности и примеры: [docs/project/testing.md](testing.md), раздел «Явный полный прогон».
