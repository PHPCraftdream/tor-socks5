# Android: восстановление соединений и проверка мостов

Исходная точка: `3c433d8`. Реализация через Rush в изолированных worktree;
перенос после проверки кода и регрессионных тестов.

| Задача | Состояние | Приёмка |
|---|---|---|
| AND-01 | Закрыта | Исходный PT из APK; отдельное владение процессами и scratch; 78 host-тестов, Clippy с `-D warnings`, Android ARM64 check пройдены |
| AND-02 | Закрыта | Android MAIN: первая попытка exit CONNECT 4 с, один повтор с обычным бюджетом; виртуальное время проверяет 4+10, default 10+10, короткий обычный бюджет и snapshot при reconfigure |
| AND-03 | Закрыта | В текущей ветке: 164 unit-теста и 6 doc-тестов прошли, 5 doc-тестов штатно ignored; строгий Clippy, workspace/all-targets check, Android ARM64 check и форматирование прошли |

Для AND-02 требуется регрессия на зависшую первую попытку и успешный повтор,
ограничение числа попыток и отсутствие повторной передачи прикладных данных.
Для AND-01 требуется регрессия на одновременную фоновую и ручную проверку.
Сетевой эффект после screen-on проверяется на телефоне отдельно от host-тестов.

Принудительная очистка PT использует pidfd: Android API 31+ и поддержка ядром.
На неподдерживаемой системе выдаётся предупреждение; небезопасного завершения
по одному числовому PID нет. Реальные exec и очистка в sandbox приложения
требуют проверки обновлённой библиотеки на устройстве.
