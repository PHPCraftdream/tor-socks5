# Проверка параллельных коммитов — 2026-09-10

Проверены `ptrs-gesher c8a87ad` и `tor-socks5 08b80d3`. Это проверка двух новых
коммитов поверх результатов восьмого раунда, а не новое полное ревью репозиториев.

## P2: TS9-01 — тесты атомарности не воспроизводят исходное окно гонки

В `08b80d3` сама production-правка корректна: проверка поколения и вставка DNS
записи используют тот же mutex, что смена поколения и очистка в `flush_dns_cache`.
Сетевое ожидание остаётся за пределами критической секции.

Однако `pre_publish_pause()` вызывается в `coalesced_doh_lookup` и отрицательном
пути `resolve_addrs` **до входа** в `store_cached_if_generation`. Поэтому два теста
`flush_landing_after_the_generation_check_*` не останавливают исполнение после
проверки поколения, несмотря на свои имена и комментарии.

Контрпример: вернуть в `store_cached_if_generation` неправильный порядок:

```rust,ignore
if DNS_NETWORK_GENERATION.load(Ordering::SeqCst) != expected_gen {
    return false;
}
let mut cache = doh_cache().lock().unwrap();
insert_capped(&mut cache, host, answer);
```

После снятия тестовой паузы эта проверка выполняется уже после `flush`, видит
сменившееся поколение и запрещает запись. Оба новых теста продолжают проходить,
хотя исходная гонка между проверкой и захватом mutex восстановлена.

Нужен управляемый барьер непосредственно перед захватом mutex публикации,
с публикацией в отдельном потоке и наблюдением старта через событие. Отрицательный
контроль должен перенести проверку поколения перед этим барьером и вызвать
падение теста. Проверка должна также сохранять свежую запись B после flush.

Места: [store_cached_if_generation](../packages/bridge-probe/src/dns.rs),
[расположение паузы](../packages/bridge-probe/src/probe/dns_resolution.rs),
[два новых теста](../packages/bridge-probe/src/tests/probe_coalesce_tests.rs).

## ptrs-gesher c8a87ad

Механизм исправления PT8-01 корректен: reload-фильтр пересчитывает интерес
зарегистрированных callsite. Исходный дефект изменяемого `filter_fn` устранён.
В используемой версии tracing-subscriber reload обновляет также максимальный
уровень для совместимости с `log`.

PT8-02 — сохранение старого файла при `enable=false` — коммит не меняет. Это
прежний открытый дефект, а не новая регрессия коммита. В подготовке ptrs-gesher
0.6.0 отдельно добавлены выключение фильтра и освобождение target, проверка
`tracing` и `log` на тех же callsite, повторное включение и ошибка перенастройки.
Из теста убрано ожидание уже синхронно записанного события.

## Остаток восьмого раунда tor-socks5

`08b80d3` не меняет следующие открытые находки:

- TS8-02, P2: прогрев через другой endpoint подтверждает неверный carrier.
- TS8-03, P2: устаревший WebTunnel endpoint получает приоритет свежего.
- TS8-04, P3: каждая вставка совместного DoH lookup сканирует весь реестр.

Подробные сценарии остаются в [ревью восьмого раунда](review-round-8-2026-09-10.md).
При проверке двух коммитов новых P0/P1 не обнаружено. Production-исправления обоих
коммитов следует сохранить; доказательство атомарности в тестах TS8-01 требует
доработки. Отдельный прогон тестов tor-socks5 в рамках этой проверки не выполнялся.
